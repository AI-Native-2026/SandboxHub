# SandboxHub 使用手册

> AI智能体沙箱平台（基于 OpenSandbox）。本文面向开发者与运维/管理员，讲清概念、功能原理与使用方法。

## 1. 产品概览

**是什么**：SandboxHub 是一个内部 PaaS，让 AI 应用与 Agent 能够**安全地执行不可信代码**——提供隔离沙箱的创建、执行、文件、网络、配额、审计与治理能力，并对外暴露统一的 REST API、API Key 与 SDK 接入方式。

**解决什么问题**：
- AI 生成的代码不可信，直接跑在生产环境等于把主机交给未知程序；
- 各团队自建沙箱重复造轮子，缺少统一的隔离、网络管控、配额与审计；
- 缺少对 AI 执行环境的可观测、成本归因与合规留痕。

**核心架构**：
```
浏览器 → nginx(8081) → BFF(8001) → OpenSandbox Server(8090) → 沙箱容器(gVisor)
                            ├─ Keycloak 认证
                            ├─ PostgreSQL 元数据/审计
                            └─ Redis 缓存
```
- **控制面**：SandboxHub BFF（FastAPI）——鉴权、租户、编排、审计、聚合。
- **数据面**：宿主上的沙箱容器，容器内注入 **execd** 提供命令/文件/终端能力。
- **上游**：OpenSandbox Server 负责容器生命周期（零改动核心）。

**为什么需要 BFF**：浏览器不直接访问沙箱与上游密钥；BFF 统一做鉴权、租户作用域、审计与代理，保证密钥不落地浏览器。

## 2. 核心概念

| 概念 | 说明 |
|---|---|
| **沙箱（Sandbox）** | 一只隔离容器 + 注入的 execd，是执行代码的最小单元。有 TTL，到期自动回收。 |
| **模板（Template）** | 预置的镜像 + entrypoint + 资源默认值，一键创建。 |
| **运行时（Runtime）** | 隔离等级：runc（共享内核）或 gVisor（用户态内核，强隔离）。 |
| **execd** | 沙箱内的执行守护，提供命令、文件、PTY、代码执行与指标接口。 |
| **端点（Endpoint）** | 沙箱内服务的访问地址，经 BFF 代理访问。 |
| **租户（Tenant）** | 逻辑隔离单元，拥有独立配额、成员、API Key 与资源作用域。 |
| **配额（Quota）** | 租户 CPU/内存/并发沙箱上限。 |
| **会话录制** | 终端会话的字节流录制，可回放用于审计。 |
| **凭据库** | 出网凭据的引用存储，注入而不暴露给沙箱。 |

## 3. 快速开始

1. **登录**：访问 `http://<host>:8081`，使用 Keycloak 账号登录（示例：`dev1` / `Passw0rd!`）。
2. **选择租户**：右上角切换租户。
3. **创建沙箱**：进入「沙箱」→ 点击「创建沙箱」→ 在弹窗中选择模板（或自定义镜像）→ 提交。
4. **使用**：进入沙箱详情：
   - **运行 → 终端**：交互式 shell（可开启录制）；
   - **运行 → 命令**：执行命令并查看流式输出；
   - **数据**：浏览/上传/下载/编辑文件；
   - **网络**：查看端点、配置出网策略；
   - **观测**：查看 CPU/内存实时指标与状态事件。
5. **销毁**：详情或列表点击「销毁」（幂等，重复销毁不报错）。

## 4. 功能详解

> 每个功能按「为什么需要 / 解决什么问题 / 没有会怎样 / 如何实现 / 使用示例」说明。

### 4.1 沙箱生命周期
- **为什么需要**：执行环境必须有明确的创建、使用与回收边界，否则资源泄漏。
- **解决什么问题**：按需创建、到期回收、暂停恢复、销毁。
- **没有会怎样**：僵尸容器耗尽宿主，资源不可控。
- **如何实现**：BFF 调用 OpenSandbox lifecycle API，并在平台 `sandbox_records` 记录归属（租户/所有者），TTL 由上游定时器管理。
- **示例**：列表页创建 → 详情页暂停/恢复/续期 → 销毁。

### 4.2 终端与命令执行
- **为什么需要**：开发者需要像本地一样交互式操作沙箱。
- **解决什么问题**：在浏览器内安全地获得 shell 与命令执行能力。
- **没有会怎样**：只能通过 SSH/脚本，无法集中审计与管控。
- **如何实现**：终端经 BFF 的 WebSocket 代理到 execd PTY（二进制帧）；命令经 BFF 转发 execd 的流式输出（NDJSON）。
- **示例**：终端执行 `python --version`；命令页运行 `pip install numpy` 看流式日志。

### 4.3 文件管理
- **为什么需要**：代码/数据需要在本地与沙箱间流转。
- **解决什么问题**：上传、下载、在线编辑、删除、移动、搜索。
- **没有会怎样**：数据交换只能靠重建镜像。
- **如何实现**：BFF 代理 execd 的 `/files`、`/directories` 接口；文本用内置编辑器。
- **示例**：数据 Tab 上传 CSV → 编辑 → 下载。

### 4.4 出网策略（Egress）
- **为什么需要**：AI 代码可能外泄数据或拉取恶意依赖。
- **解决什么问题**：默认拒绝所有出网，仅放行白名单域名。
- **没有会怎样**：沙箱可自由访问任意地址，数据外泄风险敞开。
- **如何实现**：OpenSandbox egress sidecar 透明拦截 DNS，按 FQDN 白名单放行。
- **策略模板（用在哪里）**：平台管理员在「治理 · 网络策略模板」定义可复用的 `默认动作 + 规则`；**创建沙箱时**在弹窗的「网络策略模板（可选）」中选用，平台即把该模板下发给沙箱（defaultAction + egress）。不选用则用弹窗下方的自定义出网策略。
- **注意**：`gVisor` 与 `networkPolicy` 不兼容（无 nat 表）。当前上游 `GET/PUT /networkpolicy` 恒返回 404，详情·网络页显示的是 BFF 兜底值（默认拒绝/空）；但创建时下发的策略会创建 egress sidecar 并生效。
- **示例**：网络 Tab 设置默认拒绝 + 放行 `*.pythonhosted.org`；或在创建沙箱时选择名为 `pypi` 的策略模板。

### 4.5 强隔离（gVisor）
- **为什么需要**：runc 与宿主共享内核，内核漏洞即逃逸风险。
- **解决什么问题**：用用户态内核拦截系统调用，显著增强隔离。
- **没有会怎样**：执行不可信代码时风险高。
- **如何实现**：宿主安装 `runsc`，服务端配置 `[secure_runtime] type="gvisor"`。
- **示例**：沙箱内 `uname -r` 显示 `4.19.0-gvisor`。

### 4.6 模板市场
- **为什么需要**：降低上手成本，统一镜像与默认配置。
- **解决什么问题**：一键创建标准环境（Python/Code Interpreter/Playwright 等）。
- **没有会怎样**：每次都要手填镜像与参数。
- **如何实现**：平台模板表 + 创建弹窗带出默认值；平台管理员可增删模板。
- **示例**：创建时选择「Python 3.12」，镜像自动带出且不可修改；不选模板则自定义镜像。

### 4.7 快照
- **为什么需要**：保存沙箱文件系统状态。
- **解决什么问题**：暂停/恢复与状态保留。
- **没有会怎样**：销毁即丢失环境。
- **如何实现**：调用上游快照接口（K8s 下支持 rootfs 快照恢复；Docker 下能力有限）。
- **示例**：详情·快照 → 创建快照。

### 4.8 配额管理
- **为什么需要**：多租户共享宿主，必须限制资源。
- **解决什么问题**：防止单租户吃满 CPU/内存/并发。
- **没有会怎样**：一个失控租户影响所有人。
- **如何实现**：租户配额字段 + 创建时校验（超限返回 `QUOTA_EXCEEDED`）。
- **示例**：配额页查看 CPU/内存/并发用量。

### 4.9 用量与成本
- **为什么需要**：内部成本归因与容量规划。
- **解决什么问题**：按时间统计 CPU/内存消耗与估算成本。
- **没有会怎样**：无法知道谁在消耗资源。
- **如何实现**：后台采样器每 60s 记录运行中沙箱的 CPU/内存秒数 → 汇总/趋势/Top。
- **示例**：治理·用量与成本，查看时序趋势与 Top 消耗沙箱。

### 4.10 审批中心
- **为什么需要**：敏感操作需要人工把关。
- **解决什么问题**：大配额、出网白名单、特权模板的申请与审批。
- **没有会怎样**：敏感变更无管控。
- **如何实现**：平台审批表 + 状态流转（待审/通过/驳回）。
- **示例**：发起申请 → 管理员在「待我审批」处理。

### 4.11 凭据库
- **为什么需要**：沙箱执行需要调用外部 API，但真实密钥不应暴露给代码。
- **解决什么问题**：凭据引用存储与注入。
- **没有会怎样**：密钥散落在沙箱环境变量，易被读取。
- **如何实现**：平台存储凭据引用（不回显），对接 OpenSandbox Credential Vault 注入。
- **示例**：管理员在凭据库新增 bearer 凭据。

### 4.12 会话录制
- **为什么需要**：审计与合规要求可回溯终端操作。
- **解决什么问题**：录制终端会话并回放。
- **没有会怎样**：操作无留痕，事故难追责。
- **如何实现**：BFF 终端代理在开启录制后记录 stdout/stderr 帧（base64+时间戳），断开时落库 → 会话录制页按时间轴回放。
- **详细步骤**：
  1. 沙箱详情 → **运行** → **终端**，等待状态显示「已连接」。
  2. 打开 **录制会话** 开关（不会重连终端；开关变红并显示「录制中」提示）。
  3. 在终端中执行你要记录的操作。
  4. **离开该页面**（返回列表或切换菜单）即结束会话并写入录制（约 0.5s）。
  5. 左侧 **治理 · 会话录制** → 找到该条记录 → **回放** → **播放**。
- **注意**：录制从打开开关后开始；开关默认关闭。若列表暂无，稍等 1 秒后刷新。

### 4.13 审计
- **为什么需要**：所有写操作需可追溯。
- **解决什么问题**：谁、何时、对什么、做了什么、结果如何。
- **没有会怎样**：无法追责与合规。
- **如何实现**：BFF 中间件/服务在写操作落审计表；管理员可检索与导出 CSV。
- **示例**：管理·全局审计 按 action 过滤并导出。

### 4.14 角色与权限
- **为什么需要**：不同角色能力不同。
- **解决什么问题**：内置角色（platform-admin/tenant-admin/developer/viewer）+ 自定义角色。
- **没有会怎样**：权限混乱。
- **如何实现**：Keycloak 认证 + 平台 membership 授权；前端按角色渲染、后端二次校验。
- **示例**：管理员新建自定义角色并多选权限（如 `sandbox:view`、`sandbox:create`）。

### 4.15 资源池与可观测
- **为什么需要**：降低创建延迟、掌握平台整体健康。
- **解决什么问题**：预热资源池登记 + 平台用量大盘与时序趋势。
- **没有会怎样**：创建慢、容量盲区。
- **如何实现**：资源池登记表（provider：Docker/Kubernetes）+ 聚合观测（含时序）。
- **与用户资源如何关联**：资源池按 **镜像** 关联用户沙箱——池登记某镜像的预热容量（min/max）；平台统计 **运行中且镜像匹配** 的沙箱数量作为该池的「已用」，上限取自池的 Max capacity，列表展示「已用 / 上限」。
- **示例**：管理·资源池与可观测 新建 docker 资源池（镜像 `python:3.12`，max 3）→ 创建若干该镜像的沙箱 → 该池显示 `已用 2 / 3`。

### 4.16 任务
- **为什么需要**：评测/批处理/训练需要批量创建沙箱并执行命令。
- **解决什么问题**：一次创建 N 个沙箱执行同一命令并汇总结果。
- **没有会怎样**：逐个手工创建效率低。
- **如何实现**：任务表 + 后台 runner 逐个创建沙箱、执行命令、记录结果。
- **示例**：任务页新建（镜像 python:3.12、命令、副本 2）→ 详情查看每个副本的输出与退出码。

### 4.17 产物
- **为什么需要**：执行结果（文件/图表）需要集中留存与下载。
- **解决什么问题**：从沙箱收集指定路径的文件。
- **没有会怎样**：产物随沙箱销毁而丢失。
- **如何实现**：BFF 从 execd 下载文件并存入产物表；支持下载与删除。
- **示例**：产物页「收集产物」填写沙箱 ID 与路径 `/workspace/squares.csv`。

### 4.18 Agent 托管
- **为什么需要**：编码 Agent（Claude Code/OpenCode/Codex）会读写代码、执行命令、访问网络，最需要隔离。
- **解决什么问题**：一键创建沙箱并在其中安装/运行编码 Agent。
- **没有会怎样**：Agent 直接跑在开发机/CI 上，权限过大。
- **如何实现**：基础镜像**不含** Agent；启动接口创建沙箱后**后台自动执行安装命令**。
- **示例**：Agent 托管页点击「创建并安装」→ 约 10–90s 后在终端执行 `opencode run 'Compute 1+1'`。

### 4.19 API Key 与接入
- **为什么需要**：脚本/CI/SDK 需要非交互式访问。
- **解决什么问题**：个人 API Key（请求头 `X-API-Key`）+ 多租户头 `X-Tenant-Id`。
- **没有会怎样**：只能靠浏览器会话。
- **如何实现**：平台生成密钥、存哈希、可吊销；BFF 支持 API Key 鉴权。
- **示例**：接入指南页提供 REST/CLI 与 Python 片段。

## 5. 角色与权限

| 角色 | 能力 |
|---|---|
| platform-admin | 全部：租户、模板、策略、凭据、审计、资源池、可观测、角色 |
| tenant-admin | 本租户成员/配额/用量/审批/Key；本租户全部沙箱 |
| developer | 自助创建/使用/销毁沙箱；终端、文件、任务、产物、Agent |
| viewer | 只读；无创建入口 |

## 6. 常见问题

- **销毁报 404？** 沙箱可能已被回收；平台已做幂等处理，重复销毁不再报错。
- **列表里的沙箱点开提示"上游已不存在"？** 该记录已过期或被回收；点击「刷新」会重新对账并标记为 Terminated，后台每 15 分钟自动清理已终止的沙箱，清理后不再出现在列表中。管理员也可在「管理 → 平台指标」点击「立即对账并清理」。
- **终端里 opencode 找不到？** 镜像不含 Agent，需通过「Agent 托管」创建并安装，或在终端执行安装命令。
- **出网被拒？** 检查网络策略是否默认拒绝；gVisor 下不支持 networkPolicy。
- **英文界面仍有中文？** 如发现遗漏，请反馈具体页面与文案以便补充词条。
